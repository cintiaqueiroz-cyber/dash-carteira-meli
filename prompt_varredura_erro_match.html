Prompt — Varredura de Erro de Match (BPC)

Auditoria dos itens mais representativos do portfólio BPC · Rode direto no Claude

Cole este prompt completo no Claude (Code ou Cowork com acesso a BigQuery e fetch de páginas). Troque <SEU_LDAP_AQUI> pelo seu LDAP/ASESOR antes de rodar. Ajuste "Quantidade de itens" e as palavras-chave de tamanho conforme sua vertical.
Preciso de uma varredura de erro de match nos itens de maior representatividade
do meu portfólio BPC (Buyer Price Competitiveness) no MercadoLibre.

Meu LDAP/ASESOR: <SEU_LDAP_AQUI>
Quantidade de itens: Top 20 (pode ajustar se eu pedir outro número)

FONTE DE DADOS (BigQuery):
Tabela: meli-bi-data.WHOWNER.LK_COMP_FAVORABILITIES_DETAIL

* Só tem o dia atual, sem histórico — não filtrar por data
* PI só tem o valor 'EXPENSIVE' nessa tabela inteira (não existe CHEAPER/EQUAL
  populado, mesmo a descrição da coluna dizer que deveria ter)

Query para pegar os itens (rodar sem LIMIT primeiro pra saber o ranking real
no portfólio completo, e só depois cortar pro top N):

WITH portfolio AS (
  SELECT FAVORABILITY_TYPE, SELLER_ID, SELLER_NAME, SELLER_SEGMENT,
         CAST(MELI_ID AS STRING) AS meli_id, CAST(ITE_ITEM_ID AS STRING) AS item_id,
         TITLE, BRAND, VERTICAL, DOM_AGG_1 AS domain_1, DOM_AGG_2 AS domain_2,
         PRICE_MELI AS meli_price, COMP_PRICE_RIVAL AS rival_price,
         PRICE_GAP AS price_gap_pct, VISITS_TOTAL, VISITS_EXPENSIVE,
         URL_MELI, URL_RIVAL
  FROM `meli-bi-data.WHOWNER.LK_COMP_FAVORABILITIES_DETAIL`
  WHERE ASESOR = '<SEU_LDAP_AQUI>'
    AND FAVORABILITY_TYPE = 'BOX_ALL_ABC'
    AND PI = 'EXPENSIVE'
),
totals AS (SELECT SUM(VISITS_EXPENSIVE) AS total_visits_expensive FROM portfolio)
SELECT p.*,
       ROUND(SAFE_DIVIDE(p.VISITS_EXPENSIVE, t.total_visits_expensive) * 100, 2) AS representativity_pct
FROM portfolio p CROSS JOIN totals t
ORDER BY representativity_pct DESC

O QUE PRECISO:
Para cada um dos 20 itens mais representativos, abra o link do concorrente
(URL_RIVAL) via fetch e extraia o título/nome real do produto ali (og:title,
<title>, ou heading principal). Compare com o TITLE do MeLi, procurando
divergência de:

* Tamanho (SOLTEIRO, CASAL, QUEEN, KING, VIÚVA, INFANTIL etc. — ajuste as
  palavras-chave conforme a vertical dos meus itens)
* Cor
* Firmeza/densidade (ex: colchão Firme vs Macio)
* Tipo de produto (ex: mesa de escritório vs penteadeira)

Classifique cada item:

* OK — produto do concorrente confirma o mesmo tamanho/tipo
* ERRO CONFIRMADO — conteúdo real da página confirma divergência
* SUSPEITA — fetch bloqueado (403/500), mas a slug da URL já sugere
  divergência
* NÃO VERIFICADO — bloqueado, sem pista nenhuma

Se tiver muitos itens (mais de ~25), divida em lotes e rode em paralelo via
agentes em background, pra não estourar o contexto abrindo dezenas de páginas
sequencialmente. Não insista em retry se um site bloquear (ex: Magazine Luiza
costuma dar 403) — marca como não verificado e segue.

FORMATO DA RESPOSTA:
Tabela markdown com TODOS os itens (não só os flagados), nesta ordem de
colunas:
Ranking (posição real no portfólio completo, não 1-20) | Código Item (MLB +
item_id) | Seller | Título MeLi | Represent% | Visits Exp. | Gap% | Preço
MeLi | Preço Rival | Veredito | Info Rival Extraída

Na coluna "Info Rival Extraída", use o formato: "Item no MeLi é [atributo] e
no competidor é [atributo]" — sempre nomeando o que diverge.

No final, um resumo com a contagem por veredito e destaque nos itens ERRO
CONFIRMADO e SUSPEITA (são os únicos acionáveis).
